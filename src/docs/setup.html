Local setup & reproducibility

This suite is designed for local demonstrations. The tested environment is Windows with Python 3.14. Each application retains its original framework.

Install and launch

  1. Open SETUP_PORTFOLIO.bat in the project folder. It creates a private .venv and installs requirements-tested.txt.
  2. Open START_PORTFOLIO.bat. It checks service readiness and opens this portfolio.
  3. Use a project’s demo button. Open desktop demo starts the Tkinter app.

Equivalent terminal commands, from the project root:

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r config/requirements-tested.txt
.venv\Scripts\python.exe launcher.py start
.venv\Scripts\python.exe launcher.py status
.venv\Scripts\python.exe launcher.py stop

The stop command terminates only processes owned by this launcher. An occupied, unready port is reported without killing the other process. Startup logs live in .runtime. For an import error, reinstall the tested dependencies in the same interpreter; for an occupied port, close the conflicting local service and retry.

Offline operation and optional AI

Shipped historical datasets, model artifacts, recorded examples, facts-only reports and deterministic coaching operate locally. Telemetry Lab needs a first download for uncached sessions; downloaded caches are excluded from Git. Optional Ollama runs locally on its standard service port and must already have the selected model installed. The application reports a deterministic fallback on timeout or unavailability. No key is needed for the default workflows.

Recording contract

UTF-8 JSON object: schema_version 1, a provenance object and 2–100,000 samples. A file contains one lap. Timestamps (seconds) and distance (metres) must strictly increase; timestamps are normalized to the first sample. Speed is km/h (0–500); throttle and brake are 0–1; gear is an integer from −1 to 8. Optional x/y must share a coordinate system between recordings. Optional tire_temps and tire_wear maps use FL, FR, RL, RR; the latter means percent remaining, 0–100. Unknown channels are omitted. The browser accepts up to 12 MB per file and 15 MB combined after normalization.

{"schema_version":1,"provenance":{"mode":"recorded","source":"Your supplied lap","position_units":"metres"},"samples":[{"timestamp":0,"distance":0,"speed":100,"throttle":1,"brake":0,"gear":3},{"timestamp":1,"distance":27.8,"speed":100,"throttle":1,"brake":0,"gear":3}]}

Load VER as reference and HAM as run for the shipped Silverstone pair. The run’s distance must fit inside the reference range. Braking onsets are paired conservatively within 100 metres, with mutual-nearest matching when both recordings are available; unmatched events remain unavailable. Position units in these FastF1 examples are decimetres, explicitly labelled; they are not metre-valued GPS coordinates.

Minimal race import

{"race_id":"my_race","name":"My race","circuit":"My circuit"}

Optional fields include date, laps, winner, podium, key_timeline, strategy_stints and sources. Use Download import template in the app. Unknown fields and malformed values are rejected. Imports are saved in projects/race-summariser/race_summariser/backend/races.sqlite3; back up that file before moving installations.

Reproduce data and evaluation

.venv\Scripts\python.exe src/projects/race-result-predictor/race_result_predictor/data_pipeline.py
.venv\Scripts\python.exe src/projects/race-result-predictor/race_result_predictor/model_trainer.py
.venv\Scripts\python.exe src/scripts/export_recordings.py
.venv\Scripts\python.exe src/scripts/export_race_fixtures.py

Network requests are cached locally. Dataset cutoff and retrieval time are recorded in src/data/coverage.json; model metadata records train/selection/calibration/test ranges, feature definitions and measured baselines. Load only trusted local model artifacts.

Run checks

.venv\Scripts\python.exe -B -m unittest discover -s src/tests -v
node src/tests/test_frontend.cjs
.venv\Scripts\python.exe -B src/tests/soak.py

The soak needs Replay Engineer running from the launcher and a Windows desktop session. It lasts 30 real minutes and writes src/.implementation/soak.json. Keep the app services running during the test. Shorter SOAK_SECONDS values are useful for smoke tests but do not satisfy the 30-minute acceptance check.
